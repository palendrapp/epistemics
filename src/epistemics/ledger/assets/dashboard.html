Two layers: a Bayesian observer, and whether it includes the hidden structure

1 · Report model (per session)

y = logit p̂  ~  N( ℓ + b·[forecast], τ2 ),  binned to whole %
ℓ = logit P(H | E; π, γ)  =  logit P(H) + log P(E|H) − log P(E|L)
stated accuracy q is read as σ(γ · logit q)

The same Bayesian answer (80%), reported by a precise and a noisy configuration. τ is the spread on the log-odds scale; precision is a trait.

H/L: high/low state (red-/blue-majority, high/low demand). πl: prior on the hidden structure at description level l = 1…5. Grid posterior, uniform priors: πl ∈ [0, 1], γ ∈ [0.5, 1.5], b ∈ [−0.6, 0.6], τ ∈ [0.01, 1].

2 · Three hidden structures (P(E|H); swap H↔L for P(E|L))

Dependence  (relay, copying, echo):  a1 · [ π·1{match} + (1−π)·b1 ]
Withholding  (disclosure, selection, hub):  π·1{j=0}·gm(1−g)k + (1−π)·ωk(1−ω)m+jgm(1−g)j
Uninformative  (misfiled, stale):  (1−π)·a1 + π/2

Top: the causal story; the dashed link is the hidden structure, believed with probability π. Bottom: the forecast for one example case as π goes from 0 (ignored) to 1. The dot at 0.5 is the default when the structure is named but its rate is not given.

a1, b1: chance of each report under H (a wording cue, where a case has one, multiplies π's odds by its likelihood ratio). m, j, k: good shared, bad shared, withheld; g: chance an item is good under H; ω: stated random omission rate.

3 · Noticing (second layer)

P(include) = Φ( (r + w·cl + εs − θ) / 0.3 ),  εs ~ N(0, σ2)
πl ~ logit-N(μl, ω) if included, else 0;  cl = logit μl − logit μirrelevant
stated rate = applied πl (prob. φ), else μl

Fitted inclusion when nothing hints at the structure, by rung (structure checks, from the ledger). A structure is reliably considered where its line crosses the dashed 0.8.

Rung r: 0 plain · 1 named · 2 named and asked for its rate · 3 also asked per case. θ: the rung at which a structure is included half the time when nothing hints at it. Across structures k: θk ~ N(θ̄, τθ2).

4 · Traits and the transfer test

precision = log τ;  fidelity = meanl=2…4 | statedl − π̂l |;  noticing = θ
dct = yct − meanc′≠c yc′t,   d̂ct = meant′≠t dct′
gain G = 1 − Σ(d − d̂)2 / Σd2;   p = P(Gshuffled ≥ G)

Each configuration's value relative to the other configurations, per task (battery v2). A trait is a row of one colour; a pattern that follows the columns is a task effect.

c: configuration, t: task. Shuffles permute configurations within each task, which keeps task effects and removes consistency. A trait transfers if G > 0 and p < 0.05.

    Decisions

      Experiments

      Token use

      Every figure here is recomputed by the ledger from the verified reports. The steps follow a Bayesian workflow: state the model, check that the design can recover its parameters, fit, check the fit against the data, then use it.

      1 · Model

      The report model, and what it predicts

      Each case states a prior, some evidence and how reliable its sources are. A Bayesian observer with one free assumption about the world turns the case into log-odds. The assumption is how often outlets relay each other, or how often companies withhold bad news. Stated reliabilities pass through evidence sensitivity γ, forecasts can carry a bias b, and the report gets noise τ on the log-odds scale before it is rounded to a whole percent. The parameter nodes are sliders: move them to see what a respondent with those settings would report.

      2 · Recovery

      Can the design recover what it measures?

      Before fitting agents, the fit is run on simulated respondents whose settings are known. Each point is one of 100 simulated respondents per module: its true value against its posterior mean, with the 90% interval widened to the edges of its grid cells. Red points are respondents whose interval misses the truth; about one in ten should.

      3 · Posteriors

      What each session says about the parameters

      Grid posteriors for every verified session, grouped by configuration. Each slab is a posterior density scaled to its row. The dot is the posterior mean, the thick bar the central 66% and the thin bar the central 90%. The dashed line is the uniform grid prior on the same scale, so a slab far above it means the session pinned the parameter down.

      4 · Checks

      Do the fits reproduce the reports?

      The fitted posterior predicts a distribution for every report in its session, mixing over all grid parameter values by their posterior weight. If the model describes the respondent, about 90% of reports fall inside their central 90% predictive interval. The strip shows that share for every session; select a dot, or pick a session, to see its cases.

      5 · Application

      Descriptions become priors

      In the description modules each of five source descriptions gets its own implied prior, fitted from that description's forecasts and probes. Thin lines are single sessions and the filled shape is their average; ticks under each row are the base rates the agent stated when asked directly. Formal sessions shown here use random case order. Dossiers present the same cases as realistic document bundles. Unprompted dossiers never mention relaying or selective withholding, so a prior above zero means the agent raised the possibility itself. Named dossiers add one sentence saying the mechanism exists, without its rate; asked dossiers also ask for each description's base rate.

      6 · Second layer

      How much prompting does each hidden structure need?

      Each hidden structure gets its own inclusion threshold θ, on the salience ladder: the rung at which a description that says nothing about the structure brings it into the agent's model about half the time. Thresholds are partially pooled toward the configuration's typical value θ̄. Their spread τ_θ, in rungs, says how far noticing generalises from one structure to another. The last row is the prediction for a structure not yet tested. Slabs are posterior densities; the dot is the mean, the thick bar the central 66% and the thin bar the central 90%.
