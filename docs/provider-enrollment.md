# Enroll a provider before evaluating it

The local provider workflow now connects identity resolution to collection and issuance. It uses the existing pinned devnet adapter; it does not register an agent, submit a transaction, host public artifacts or collect payment. A real demonstration still requires a registry asset controlled by the operator and a new agent evaluation under its canonical subject ID.

The executable preview uses an invented registry identity and a **new synthetic evaluation collected after enrollment**. It exercises actual signatures and private loopback retrieval through the machine consumer. Its decision is ineligible because the response origin is synthetic. It is never promoted into a real-agent result or a live registry observation.

## Enrollment and issuance

1. Resolve the pinned registry/Core identity and check that the enrollment signer is its current controller or authorized operational wallet.
2. Create the canonical participant descriptor before collection. A new `provider-enrollment.v1` signature commits to its exact bytes, the registry snapshot bytes, configuration digest, evaluator protocol version/hash, expected issuer, validity window and enrollment ID.
3. Collect using that exact descriptor. Do not rewrite a completed report's subject or configuration to fit the enrollment.
4. Before issuance, verify the enrollment and exact artifacts, resolve authority again and reject transfer, stale signer authorization, deployment drift, a regressed RPC slot, altered participant metadata, a changed protocol or a run started before enrollment. Live issuance requires agent-origin responses; the local preview requires synthetic origin.
5. Generate the existing passport attestation, provider binding and initial issuer status. Save a local issuance receipt connecting their hashes to the enrollment, plus the post-evaluation registry snapshot. The receipt is an unsigned audit aid, not a bearer authorization.

The enrollment domain is `epistemics/provider-enrollment-signature/v1\n`. The payload is string-only and uses the existing UTF-16-key-order/ECMAScript-JSON canonicalization. Its schema is generated by `scripts/consumer_schemas.py`. Existing report, passport, provider-binding and status signature domains and bytes are unchanged.

Enrollment establishes a signed operator association before collection. It does not independently attest the execution environment, model identity, wall-clock time or uninterrupted authority throughout the evaluation. Registry observations still trust the chosen RPC. Only the before/after snapshots are checked; an ownership transfer away and back between them is outside this check. Configuration, issuer, controller, operational wallet and payment payee remain distinct.

The TypeScript issuer validates source/passport structure, exact-byte hashes and metadata bindings. Scientific derivation must still be verified by the Python passport tooling. A signature does not establish the accuracy of the analysis.

## Commands

Run the fully offline preview, writing only private artifacts under an unused directory:

```sh
pnpm provider-preview output/provider-preview
```

The preview sends no RPC request, service request or payment and saves no signing keys. Its artifact server exists only while the preview runs. It produces an enrollment, unchanged source/passport bytes, signed attestation/binding/status, registry snapshots, receipt and consumer decision. Generated artifacts stay outside Git.

For an existing owned devnet identity, prepare a configuration descriptor with `model`, `model_version`, `configuration_sha256` and optional `temperature`. The configuration digest represents the evaluated configuration, not a hash of this small descriptor. Supply the actual evaluator's protocol version and implementation digest:

```sh
pnpm provider enroll --directory output/provider-enrollment \
  --asset OWNED_AGENT_ASSET --authority-keypair PRIVATE_AUTHORITY_KEYPAIR \
  --issuer ISSUER_PUBLIC_KEY --configuration PRIVATE_CONFIGURATION_DESCRIPTOR \
  --protocol-version PROTOCOL_VERSION --protocol-sha256 PROTOCOL_DIGEST \
  --expires CANONICAL_UTC_TIMESTAMP
```

Use the emitted `participant.json` when creating the supported core or investigation collection. Complete and verify its source/passport with the Python evaluator. The new auxiliary diagnostic does not yet have a passport adapter and cannot be issued through this flow.

```sh
pnpm provider issue --directory output/provider-enrollment \
  --authority-keypair PRIVATE_AUTHORITY_KEYPAIR --issuer-keypair PRIVATE_ISSUER_KEYPAIR \
  --passport PRIVATE_PASSPORT --report PRIVATE_SOURCE_REPORT \
  --passport-uri https://YOUR_HOST/passport.json \
  --attestation-uri https://YOUR_HOST/attestation.json \
  --endpoint https://YOUR_PROVIDER/research --payee PAYEE --payment-asset ASSET \
  --expires CANONICAL_UTC_TIMESTAMP
```

This prepares the `issued` directory locally. The existing [consumer hosting and decision commands](machine-consumer.md#operator-commands) can serve its explicit artifact map and status folder through a private loopback preview. Registry metadata publication, public hosting and service purchase remain separate steps. A loopback mirror of an HTTPS URI does not make that URI publicly available.

The CLI refuses existing enrollment/issuance directories. If a write is interrupted, inspect the partial directory; it does not pretend to implement the later hosted job ledger or crash reconciliation. No human identity publication is supported.
